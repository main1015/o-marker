# o-marker Chrome 扩展对标 Raindrop.io 重塑改造方案

本文档详细定义了 **o-marker Chrome 浏览器插件** 全面对标行业顶级标杆 **Raindrop.io** 的重塑改造方案、交互模型、视觉规范与技术实现。

---

## 一、 现状痛点与 Raindrop.io 标杆差异剖析

在先前的初始实现中，插件 Popup 采用了传统的“表单提交式”设计，与 Raindrop.io 流畅的高级交互存在明显差距：

| 体验维度 | 当前实现 (旧版) | Raindrop.io 标杆体验 (新版目标) | 重塑目标 |
| :--- | :--- | :--- | :--- |
| **交互心智** | 手动表单：打开后必须浏览表单并点击底部大按钮 `💾 保存到 o-marker`。 | **打开即存 (Instant Auto-Save)**：用户点击插件图标时，后台已静默保存入库，界面即刻显示 `✓ 已保存`。 | 彻底实现**零摩擦收集**。 |
| **标题与备忘录** | 静态纯文本展示标题和 URL，无法在插件内二次编辑或补充想法。 | **原地无缝编辑 (Inline Edit)**：标题为自然文本输入行；提供 **Note (备忘笔记)** 多行文本域。 | 收集即加工，随时沉淀想法。 |
| **文件夹选择** | 原生 HTML 粗糙 `<select>` 标签 + 突兀的新建文件夹输入框。 | **卡片式抽屉选择器 (Folder Drawer)**：展示为优雅的文件夹胶囊，点击滑出支持即时搜索与创建的弹层。 | 视觉精致、层级清晰。 |
| **标签交互** | 单行普通字符串输入框，需要手动输入逗号分隔符。 | **动态胶囊系统 (Tag Chips)**：键盘输入回车/逗号立即转化为独立胶囊，支持快捷删除与推荐候选。 | 交互反馈直观高效。 |
| **顶栏与操作** | 生硬的 `保存 / 书签库` Tab 切换，占用大量空间。 | **精简操作条**：左侧展示已保存状态与移除按钮（🗑️），右侧集成多语言选择与标星（⭐️）。 | 聚焦当前收藏动作。 |
| **多标签会话打包** | 在主卡片下方硬塞大块“会话快照”卡片，割裂单页保存视觉。 | **收敛至底栏轻量入口**：一键归档当前窗口全部标签页，不喧宾夺主。 | 主次分明，界面通透。 |

## 二、 核心架构与交互模型设计

```
┌──────────────────────────────────────────────┐
│  [✓ 已保存]  [🗑️]        [⚙️] [⭐️] [🌐 语言] [✕] │  <- 顶栏状态与设置/动作
├──────────────────────────────────────────────┤
│  ┌────┐                                      │
│  │ 图 │  [可原地编辑的标题 (Inline Title)]      │  <- 头部图文区
│  └────┘  https://example.com/path...         │
│                                              │
│  [ 备忘笔记 Note: 添加个人见解或摘要... ]       │  <- 备忘录文本域
├──────────────────────────────────────────────┤
│  📁 目标文件夹: [ 📂 工作资料 (点击切换) ⌵ ]   │  <- 精致文件夹选择抽屉
├──────────────────────────────────────────────┤
│  🏷️ 标签: [技术 ✕] [设计 ✕] [输入标签 +回车]  │  <- Tag Chips 交互胶囊
├──────────────────────────────────────────────┤
│  [📦 保存当前窗口全部标签页]    [在 Web 打开 ↗] │  <- 底栏快捷辅助区
└──────────────────────────────────────────────┘
```

### 1. 即开即存 (Auto-Save on Mount)
* 当用户点击插件图标，Popup 挂载执行 `useEffect`：
  1. 静默调用 Chrome API 获取当前活跃标签页（`title`, `url`, `favIconUrl`）；
  2. 自动调用服务端 `POST /api/bookmarks`，触发后端查重合并（Upsert）机制；
  3. 顶栏实时呈现绿色微动画与已保存状态；
  4. 用户如果只需收藏，打开图标看到勾选后即可直接关闭；若需定制分类，则在界面内微调。

### 2. 原地属性修改与防抖同步 (Auto-Sync on Change)
* 用户在弹窗内就地修改**标题 (Title)**、**备忘笔记 (Note)**、切换**文件夹 (Collection)**、增删**标签胶囊 (Tags)**、切换**标星收藏 (Favorite)** 时：
* 系统通过 350ms 防抖自动发起 `PATCH /api/bookmarks/:id` 同步至后端数据库；
* 服务端原子更新所有字段，在 Web 端卡片即时展示醒目备注、黄色星标徽章以及多维分类。

### 3. Tag Chips 交互规范
* 键盘监听 `Enter`、`，` 或 `,` 时，将当前输入文本转化为胶囊组件；
* 胶囊内展示标签名与移除图标 `✕`，点击即从数组中剔除；
* 支持键盘 `Backspace` 在输入框为空时快捷删除前一个胶囊。

### 4. 文件夹选择抽屉 (Folder Picker Drawer)
* 默认呈现为带有文件夹 Emoji/图标的优雅胶囊；
* 点击触发弹出层抽屉，展示现有文件夹列表及未分类项，支持顶部快速模糊过滤与一键新建。

### 5. 删除与撤销恢复机制 (Delete & Restore)
* **移入废纸篓**：点击顶栏 🗑️ 图标，向服务端发起 `DELETE /api/bookmarks/:id`，书签软删除转入回收站（`status: 'TRASH'`）；
* **实时撤销恢复**：顶栏立即显示“🗑️ 已移入废纸篓”，并提供“↩️ 恢复”按钮，点击发起 `PATCH` 带 `action: 'restore'` 即可毫秒级撤销恢复；
* **防抖安全隔离**：书签处于已删除状态时，自动阻断任何字段的静默防抖同步，杜绝误覆写。

### 6. 云端/私有服务地址设置与连通性检测 (Server Endpoint Settings)

* **痛点解决**：先前插件硬编码 `http://localhost:7364`，无法支持用户将 o-marker 部署至云服务器、NAS、远程 VPS 或自定义端口。
* **交互设计**：
  * 顶栏右侧新增 ⚙️ **设置图标**，点击呼出轻量“连接设置抽屉 (Settings Drawer)”。
  * **服务地址输入框**：支持填入完整云端 URL（如 `https://omarker.example.com` 或 `http://192.168.1.100:7364`），默认值为 `http://localhost:7364`。
  * **连通性测试 (Test Connection)**：一键发起心跳检测请求（`GET /api/maintenance`），实时显示绿色 `✓ 连接正常` 或红色 `✕ 无法连接服务器`，并给出错误排查提示。
  * **存储与持久化**：统一存储至 `chrome.storage.local`（键名 `omarker_server_url`），所有 API 请求动态基于此配置拼接，确保即时生效且离线隔离。

## 三、 多语言 (18 种语种) 词条对齐

新交互界面所涉及的所有文案将严格同步维护在 `apps/extension/src/locales/` 的 18 个独立语种模块中：
* `saved`: 已保存
* `saving`: 保存中
* `remove_bookmark`: 移入废纸篓
* `title_placeholder`: 书签标题
* `note_placeholder`: 添加备忘笔记或描述...
* `select_folder`: 选择文件夹
* `no_folder`: 未分类
* `add_tag_chip`: 输入标签并按回车
* `save_window_tabs`: 保存当前窗口全部标签页
* `open_web_dashboard`: 在 Web 控制台打开
* `create_folder`: 新建文件夹
* `settings_title`: 服务设置
* `server_url_label`: 服务端地址 (Server URL)
* `server_url_placeholder`: 例如 http://localhost:7364
* `test_connection`: 测试连接
* `connection_success`: 连接成功，服务正常
* `connection_failed`: 连接失败，请检查地址或网络
* `save_settings`: 保存设置

## 四、 落地推进步骤

1. **第 1 步**：完善扩展端国际化字典词条（支持 18 国语言独立文件，包含设置与连通性文案）。
2. **第 2 步**：构建统一 API 请求基座与配置中心 `api.ts`（支持自定义云端 Host，自动读取与持久化 `omarker_server_url`）。
3. **第 3 步**：开发独立组件 `SettingsDrawer.tsx`（实现服务端地址配置、连通性实时检测与一键保存）。
4. **第 4 步**：开发独立组件 `TagInput.tsx`（实现 Chip 胶囊输入、删除与回车交互）。
5. **第 5 步**：开发独立组件 `FolderPicker.tsx`（实现卡片式下拉抽屉与快捷检索/创建）。
6. **第 6 步**：重构 `popup.tsx`，实现即开即存、原地编辑、防抖同步、顶栏设置与精简操作条。
7. **第 7 步**：构建验证与类型检查（`npx tsc --noEmit`），确保与服务端 API 100% 互通。

## 五、 状态机生命周期隔离与顶栏弹性布局规范

针对 360px 宽度弹窗环境及多语言长文案，建立严格的四态隔离与排版规范：

### 1. 严格四态隔离模型
1. **控制台/系统保留页态 (`system_page`)**：
   - 当浏览器位于 `chrome://` 或 o-marker 管理后台（`localhost:7364`）时，拦截书签自动创建。
   - 顶栏展示紧凑徽章 `🖥️ 控制台页面`（不折行）。
   - 主体区呈现专属空态卡片（明确说明后台无需重复收藏，提供“打开控制台”外链），不显示收藏详情表单。
2. **已在废纸篓态 (`isDeleted`)**：
   - 顶栏展示 `🗑️ 已在废纸篓`。
   - 主体区呈现废纸篓说明及一键恢复按钮 `[↩️ 从废纸篓恢复书签]`。
3. **未收藏态 (`!bookmarkId`)**：
   - 顶栏展示 `⚪ 未收藏`。
   - 主体区呈现保存引导与大按钮 `[＋ 保存到 o-marker]`，支持手动一键存入。
4. **已保存态 (`bookmarkId && !isDeleted`)**：
   - 顶栏展示 `✓ 已保存`，以及 🗑️ 删除与 ⭐️ 星标快捷操作。
   - 主体区呈现原地编辑表单（标题、备注、分类目录、标签胶囊），输入实时防抖（350ms）同步云端。

### 2. 顶栏弹性排版
- 顶栏高度固定 `h-11 shrink-0`，采用 `flex justify-between items-center`。
- 左侧状态徽章与提示文本增加 `truncate` 和 `max-w`，严禁折行撑开顶栏高度。
- 右侧功能按钮组（星标、设置、多语言）采用固定间距 `gap-1.5`，确保多语言下拉框与小图标在各类屏幕与语种下均不变形。
