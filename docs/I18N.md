# o-marker 国际化 (i18n) 架构与多语言配置规范文档

本文档详细说明了 **o-marker**（涵盖 Web 服务端控制台与 Chrome 插件端）的多语言国际化架构、语种梯队规划、代码规范及扩展开发指南。

---

## 一、 语种分级与规划策略 (Tier Strategy)

根据全球互联网受众规模、付费转化能力（Tier 等级）与业务战略出海方向，o-marker 规划并已全面落地以下 **18 种主流语言**：

### 1. 核心高频语种（全球基础标配 - Tier 1）
绝大多数全球化互联网产品首发支持的核心语种：
* **简体中文 (`zh`)**：`🇨🇳 简体中文` —— 涵盖大中华区及庞大的海外华人社群（系统核心语言）。
* **繁体中文 (`zh-TW`)**：`🇭🇰 繁體中文` —— 涵盖中国港澳台地区及传统华人市场。
* **英语 (`en`)**：`🇺🇸 English` —— 全球通用第一大商业与技术语种。
* **日语 (`ja`)**：`🇯🇵 日本語` —— 高 ARPU（每用户平均收入）市场，对本地化要求极高。
* **韩语 (`ko`)**：`🇰🇷 한국어` —— 高渗透率的成熟数字消费与效率工具核心市场。

### 2. FIGS 梯队（欧洲主流四强 - European Core）
欧洲市场最基础也是最经典的本地化组合（EFIGS）：
* **法语 (`fr`)**：`🇫🇷 Français` —— 覆盖法国、比利时、瑞士及非洲法语区。
* **德语 (`de`)**：`🇩🇪 Deutsch` —— 覆盖德国、奥地利、瑞士（DACH 核心经济圈）。
* **西班牙语 (`es`)**：`🇪🇸 Español` —— 覆盖西班牙及庞大的拉丁美洲市场。
* **意大利语 (`it`)**：`🇮🇹 Italiano` —— 南欧核心经济体。

### 3. 高人口与战略出海语种（新兴大市场 - Emerging Markets）
根据业务拓展与全球出海目标所补充的高增长语种：
* **葡萄牙语 (`pt`)**：`🇧🇷 Português` —— 巴西为拉美前列的互联网消费大国，优先采用巴西葡语。
* **俄语 (`ru`)**：`🇷🇺 Русский` —— 覆盖俄罗斯及东欧、独联体国家。
* **阿拉伯语 (`ar`)**：`🇸🇦 العربية` —— 中东与北非核心高净值语种（具备 RTL 文本支持）。
* **印地语 (`hi`)**：`🇮🇳 हिन्दी` —— 印度本土庞大移动互联网用户群。
* **东南亚重点语种**：
  * **越南语 (`vi`)**：`🇻🇳 Tiếng Việt` —— 东南亚高速增长的开发者与知识市场。
  * **印尼语 (`id`)**：`🇮🇩 Bahasa Indonesia` —— 东南亚第一大人口消费市场。
  * **泰语 (`th`)**：`🇹🇭 ไทย` —— 东南亚活跃的年轻化数字消费市场。

### 4. 欧洲成熟市场补充 (European Expansion)
* **荷兰语 (`nl`)**：`🇳🇱 Nederlands` —— 西欧极高人均科技与数字生产力市场。
* **波兰语 (`pl`)**：`🇵🇱 Polski` —— 中东欧最具规模的研发外包与工程师群体。

## 二、 架构设计与工程目录组织

为避免将所有语种堆砌在单个巨大的字典文件中导致代码臃肿、合并冲突，o-marker 遵循 **KISS 原则** 与 **高内聚低耦合** 设计，双端（Web 控制台与 Chrome 插件端）均采用**完全独立的单语言模块架构**：

```bash
# 1. 服务端 / Web 控制台国际化目录
apps/server/src/locales/
├── zh.ts          # 简体中文（基础键值模板基准）
├── zh-TW.ts       # 繁体中文
├── en.ts          # 英语
├── ja.ts          # 日语
├── ko.ts          # 韩语
├── fr.ts          # 法语
├── de.ts          # 德语
├── es.ts          # 西班牙语
├── it.ts          # 意大利语
├── pt.ts          # 葡萄牙语
├── ru.ts          # 俄语
├── ar.ts          # 阿拉伯语
├── hi.ts          # 印地语
├── vi.ts          # 越南语
├── id.ts          # 印度尼西亚语
├── th.ts          # 泰语
├── nl.ts          # 荷兰语
├── pl.ts          # 波兰语
└── index.ts       # 语言导出聚合中心、Locale 类型、LANGUAGES 数组、getTranslation 函数

# 2. Chrome 插件端国际化目录
apps/extension/src/locales/
├── zh.ts
├── zh-TW.ts
├── en.ts
├── ... (与服务端完全对齐的独立语种模块)
└── index.ts       # 插件专用轻量导出聚合中心、getExtTranslation 函数
```

## 三、 语言代码规范与最佳实践

### 1. 多语言代码规范 (BCP 47 / ISO 639-1)
* 统一采用国际标准化代码命名：
  * 基础语种：`zh`, `en`, `ja`, `ko`, `de`, `fr`, `es`, `it`, `pt`, `ru`, `ar`, `hi`, `vi`, `id`, `th`, `nl`, `pl`。
  * 区域扩展：`zh-TW`（繁体中文）。

### 2. UI 与国旗对应规范
* **避免语种与国旗死板等同**：在代码和 UI 下拉菜单中，文本始终以该语种的**母语原生文字**标注（例如：`العربية`, `हिन्दी`, `Tiếng Việt`, `ไทย`），国旗仅作为辅助识别元素，符合全球主流交互规范。
* **高对比度激活状态**：下拉菜单项在当前激活时采用高明度亮橙色底色（`bg-[#E65100]` + `text-white`），未选中项悬浮浅灰（`hover:bg-slate-100`），保证各个国家用户在不同屏幕下的清晰可读性。

### 3. 阿拉伯语 (RTL) 支持规范
* 阿拉伯语属于从右至左（RTL）书写系统。
* 当系统语言设置为 `ar` 时，文本自动遵循自然阅读流向；排版中避免硬编码 `text-left` / `text-right`，推荐结合弹性盒子 `flex-row` 及自然文字流向保障界面美观。

## 四、 状态管理与持久化机制

| 客户端端点 | 存储介质 | 存储键 | 联动更新机制 |
| :--- | :--- | :--- | :--- |
| **Web 控制台 (Next.js)** | `localStorage` | `omarker_locale` | 通过全局自定义事件 `omarker_locale_changed` 驱动全量客户端组件（`useI18n`）即时重绘，无需整页刷新。 |
| **Chrome 插件 (Extension)** | `chrome.storage.local` / `localStorage` | `omarker_locale` | `LanguageSelector` 触发时回调 `onLocaleChange`，立即重渲染 Popup 界面状态。 |

## 五、 如何添加新语言？（开发者操作指南）

若未来需要扩充新的语种（例如土耳其语 `tr`）：

1. **创建单语言字典文件**：
   在 `apps/server/src/locales/` 和 `apps/extension/src/locales/` 下分别创建 `tr.ts`：
   ```typescript
   import { zh } from './zh'

   export const tr: typeof zh = {
     all_bookmarks: 'Tüm Yer İşaretleri',
     // ...对齐所有键名
   };
   ```
2. **在 `index.ts` 注册新语言**：
   ```typescript
   import { tr } from './tr'

   export type Locale = ... | 'tr';

   export const LANGUAGES = [
     // ...
     { code: 'tr', name: 'Türkçe', flag: '🇹🇷' }
   ];

   export const translations = {
     // ...
     tr,
   };
   ```
3. **验证类型与构建**：
   - 运行 `npm run build`（服务端）和 `npx tsc --noEmit`（插件端）。
   - `typeof zh` 会自动检测是否有遗漏的翻译字段，实现强类型静态编译保障。
